## 1. 全体像: 電圧から機体の動きまで

yuho のプラントは，次の順につながっています．それぞれに「モデル」と「その値の決め方」があります．

```
 電池(2S LiPo)
   │  duty = 電圧 / 電池電圧                       … 2.1 電源のモデル
   ▼
 モーター + ギア + タイヤ(左右それぞれ)
   │  電圧 = 摩擦 + 速さの分 + 加速の分              … 2.2 車輪のモデル(FF の式)
   │  (超信地旋回では横にこする摩擦が加わる)         … 2.3 超信地旋回の摩擦
   ▼
 車輪の速さ v_L, v_R(エンコーダで測る)
   │  v = (v_L + v_R)/2，ω = (v_R − v_L)/T          … 2.4 寸法と運動学(実効値)
   ▼
 機体の並進 v と回転 ω(ω はジャイロでも測る)
   │  曲がると外へずれ，出口の向きに遅れる           … 2.5 旋回中の機体(スリップなど)
   ▼
 迷路の中の位置
```

制御はこのモデルを2通りに使います．

- **FF(フィードフォワード)**: モデルの逆を計算して，目標どおりに動くのに要る電圧や，曲がり始める位置を先に決めます．
- **FB(フィードバック)**: モデルとのずれだけを，PI と外側のループ(位置・角度)で直します．

yuho の方針は「FF が主役で，FB は残りを直す」です(`development_log.md` 3.6 (4))．
そのため，モデルの精度がそのまま走りの精度になります．

## 2. 今のモデル

### 2.1 電源のモデル: 電圧で考える

制御の出力は PWM ではなく**モーターにかける電圧 [V]** です．最後に電池電圧で割って duty にします．

```c
// app/control_loop.c
if (vbat < VELOCITY_VBAT_MIN_V) vbat = VELOCITY_VBAT_MIN_V;   // 5.0V(電池がないときの 0 割り防止)
s_pwm.left  = VoltageToPWM(ff_l + out.left_mm_s,  vbat);      // duty = 電圧 / vbat × PWM_MAX
```

- **モデル**: 「PWM の duty × 電池電圧 = モーターにかかる電圧」．
- **理由**: 電池は 8.4V(満充電)から 7V 前後まで下がります．duty で考えると，同じ duty でも出る電圧が 10% 以上変わり，ゲインと FF の効き方がずれます．電圧で考えれば，電池の減り方によらず同じ式が使えます．
- **電池電圧**: PC0 の分圧(33k/20k)を ADC で読み，IIR(時定数 約 10ms)でならしています．
- **限界**: 走っている間は電池の電圧が下がります(ログで最低 6.73V)．モデルが要求する電圧がこれを超えると出せません(2.2 の計算では，1.5m/s・2000mm/s² でも約 2V なので，今の速さでは余裕があります)．

### 2.2 車輪のモデル: FF の式

車輪1つについて，次の式で「要る電圧」を見込みます(`app/control_loop.c`)．

```
電圧 = FRIC × sign(v*)  +  GAIN × v*  +  ACC × a*
        摩擦(一定)          速さに比例      加速に比例
```

`v*`，`a*` は**目標**の車輪の速さと加速度です(実測は使わない．2自由度制御)．

| 項目 | 左 | 右 | 意味 |
|---|---|---|---|
| `VELOCITY_FF_FRIC` | 0.32 V | 0.16 V | クーロン摩擦．速さによらず一定 |
| `VELOCITY_FF_GAIN` | 0.00075 V/(mm/s) | 0.00050 V/(mm/s) | 逆起電力と粘性摩擦の分 |
| `VELOCITY_FF_ACC` | 0.000275 V/(mm/s²) | 0.000275 V/(mm/s²) | 機体を加速するのに要る分 |

**左右で値が違う理由**: 左右の駆動系の重さ(摩擦)が違います．右は車軸のねじの締め方で FRIC が 0.53V → 0.16V と大きく変わりました(3章)．

**この式は「1次遅れモデルの逆」として読めます**(計算)．
式を v について書き直すと，

```
ACC × dv/dt + GAIN × v = 電圧 − FRIC × sign(v)
→  T × dv/dt + v = K × (電圧 − FRIC × sign(v))      K = 1/GAIN，T = ACC/GAIN
```

となり，「不感帯つきの1次遅れ」のモデルと同じ形です．yuho の値を入れると，

| | 左 | 右 |
|---|---|---|
| 速さのゲイン K = 1/GAIN | 1333 mm/s/V | 2000 mm/s/V |
| 時定数 T = ACC/GAIN | 0.37 s | 0.55 s |

になります．yuho はこの K と T を直接測ったのではなく，定常の電圧と加減速中の電圧から FF の係数として合わせました(3章)．それでも結果は1次遅れのモデルになっています．

**要る電圧の目安**(計算．左の値):

| 走り方 | 電圧 |
|---|---|
| 300mm/s で巡航 | 0.55 V |
| 500mm/s まで 2000mm/s² で加速中 | 1.25 V |
| 1500mm/s まで 2000mm/s² で加速中 | 2.00 V |

### 2.3 超信地旋回の摩擦

その場で回るときはタイヤが横にこすれるので，2.2 の式では足りません．直進の目標が 0 で回転の目標があるときだけ，回る向きに次の電圧を足します．

| | 左の車輪 | 右の車輪 |
|---|---|---|
| 左回り(反時計回り) `PIVOT_FF_FRIC_CCW_*` | 0.57 V | 0.69 V |
| 右回り(時計回り) `PIVOT_FF_FRIC_CW_*` | 0.64 V | 0.76 V |

- 回る向きで値が違います．ただし，右回りはいつも左回りの後に回しているので，順番の影響が混ざっている可能性があります．
- 速さに比例するのか一定なのかは，まだ確かめていません(約 100mm/s のログだけで決めた)．

### 2.4 寸法と運動学: 実効値

エンコーダのパルスを距離に，左右の車輪の速さを機体の回転に直すのに，寸法を使います．
どちらも**ノギスで測った値ではなく，走りに合わせた実効値**です．

| 項目 | 設計・実測 | 今の値(実効値) | 合わせ方 |
|---|---|---|---|
| タイヤの直径 `WHEEL_DIAMETER_MM` | 23.35 mm(ノギス) | 23.81 mm | 1080mm を 300/800mm/s で走らせ，どちらも約 2% 行き過ぎた比で直した |
| トレッド `TREAD_WIDTH_MM` | 57.90 mm(設計) | 64.75 mm | 超信地旋回で，ジャイロの角速度が (v_R − v_L)/57.90 の 0.912 倍だった比で直した．直径を変えたとき同じ割合で直した |

```
v = (v_L + v_R)/2，ω = (v_R − v_L) / TREAD       (logic/state_estimation/kinematics.c)
```

- 実効値には，タイヤの接地点のずれ，タイヤの潰れ，横滑りなどがまとめて入ります．
- 直径の行き過ぎが**速さによらず同じ割合**だったので，「滑り」ではなく「換算のずれ」と判断しました．

### 2.5 旋回中の機体: スリップとスリップ以外の遅れ

スラロームで曲がると，機体は車輪とジャイロから計算した軌道どおりには進みません．
曲がった後に**外へずれ**，**出口の向きに遅れ**ます．これを次の2つのモデルで扱います(`logic/control/slalom.c`)．

**(1) スリップ角**(1次遅れ．ユーザーが 2026-10-08 に定義した)

```
進む向き = 機体の向き − β
dβ/dt = (K × v[m/s] × ω[rad/s] − β) / C        (C = 0 なら β = K v ω)
```

- β は外(曲がる中心の反対)へずれる向きを + とします．
- K v ω は横加速度に比例します．横加速度が大きいほど，タイヤが横に滑る角度が大きいということです．
- 今の値: `SLALOM_SLIP_K` = 0.0219，`SLALOM_SLIP_C_S` = 0.02 s．
  C はまだ決まっていません．0〜0.05 で変えても，700mm/s までの調整値の違いは 1mm 以内でした(MATLAB で計算)．

**(2) スリップ以外の遅れ**

- `SLALOM_EXTRA_LAG_MM` = 7.5mm．**速さによらず一定**の距離だけ，出口の向きに遅れるとします．
- 原因はまだ分かっていません(候補: 曲がっている間に車輪が前後に滑り，車輪で測った距離が実際より長くなる，など)．

**使い方**: 機体は選んだ速さでこの2つを計算し，ずれを打ち消すように前後のオフセット(直進の長さ)を直します．
500mm/s では，前を −6mm(早く曲がり始める)，後ろを +12.4mm(長く進む)にします．
速さごとの調整値は持たず，1つのモデルで 300〜600mm/s(以上)をまかなう方針です．

### 2.6 モデルの上のフィードバック

モデルで出し切れない分を，次のループで直します(値は `params.h`)．

```
車輪の目標 = (v_ref + POSITION_KP × (s_ref − s)) ∓ (ω_ref + ANGLE_KP × (θ_ref − θ) + ANGULAR_KP × (ω_ref − ω)) × TREAD/2
電圧      = FF(目標だけから) + PI(車輪の目標 − 実速度)
```

| ループ | ゲイン | 速さの目安(計算) |
|---|---|---|
| 車輪速度の PI | KP 0.015 V/(mm/s)，KI 0.0376 V/(mm/s)/s | 帯域 約 55 rad/s(時定数 約 18ms) |
| 角度 | ANGLE_KP 25 /s，ANGULAR_KP 0.5 | 角度のずれは時定数 (1+0.5)/25 = 0.06 s で縮む |
| 位置 | POSITION_KP 10 /s | 位置のずれは時定数 0.1 s で縮む |

**車輪速度のループの帯域は，左右で同じになります**(計算)．
2.2 の1次遅れモデル K/(Ts+1) に P のゲイン KP をかけると，速い所では一巡の伝達関数が KP·K/(T·s) になるので，
ゲインが 1 になる角周波数は ω_c ≈ KP·K/T = KP/ACC です．
ACC は左右とも 0.000275 なので，K と T が左右で違っても ω_c = 0.015/0.000275 ≈ 55 rad/s で同じになります．
外側のループ(0.06〜0.1 s)より 3〜5 倍以上速いので，「内側は十分速い」という外側の設計の前提とも合っています．

### 3.2 段階ごとの経緯

#### (1) 骨組み: 値はまだ仮(10-02)

速度の PID と運動学の形だけを作りました．ゲインは KP = 1 の仮の値で，寸法は「TODO: 実測」のままでした．
この時点ではまだ「モデル」はなく，PID だけで回していました．

#### (2) 電圧の FF を入れる(10-03)

ここで今のモデルの骨格ができました．

- **出力を電圧にした**: PWM 単位で調整していた PI(Kp = 5，Ki = 20 [PWM/(mm/s)])を，Vbat ≈ 7.9V(1V ≈ 531.5 PWM)で電圧の単位に直しました(KP 0.0094，KI 0.0376)．
- **摩擦と速さの項**: 床の上で定常走行させ，2つの速さで電圧を測って直線で近似しました．
  - 左: 0.47V @200mm/s，0.55V @300mm/s → FRIC 0.32V，GAIN 0.00075
  - 右: 0.51V @200mm/s，0.56V @300mm/s → FRIC 0.41V，GAIN 0.00050
- **加速の項**: 台形(±2000mm/s²)の加速中と減速中の電圧から，摩擦と速さの分を引いて加速度で割り，**加速と減速で平均**しました．摩擦は加速でも減速でも同じ向きにかかるので，平均すると打ち消されます．→ ACC 0.00025
- 止まっているときは PI の積分を捨てる仕組み(`VELOCITY_STOP_RESET_MM_S`)を入れました．
  後で位置と角度の制御を常に効かせるようにしたので，今はこの仕組みは働きません(両方を切ったときだけ働く)．

#### (3) 超信地旋回で寸法と摩擦が足りないと分かる(10-06)

超信地旋回のログで，2つのずれが見つかりました．

- **ジャイロの角速度が，車輪から計算した値の 0.912 倍しかなかった** → トレッドを 57.90 / 0.912 = 63.50mm(実効値)にしました．次のログ2本で比は 0.995 / 1.000 になりました．
- **実際にかけた電圧が，直進用の式より 0.75〜0.84V 大きかった**(タイヤが横にこすれる) → 旋回のときだけ足す摩擦 FF を作りました．
  - 最初は左右とも 0.80V にしました．
  - 左の I 項が −0.25V 前後(多すぎ)だったので 0.65V にしたら，符号が逆になりました(少なすぎ)．
  - そこで 0.80V と 0.65V のときの I 項から**直線で補間して，I 項が 0 になる 0.70V** にしました．

結果: 角速度の補正の最大が 133 → 約 60dps，車輪の速さの目標に対する比が 0.79〜0.88 → 0.93〜1.05 になりました．

#### (4) I 項を目盛りにして詰める(10-07)

この日は「I 項を見て FF を直す」をくり返しました．

- **右の摩擦が足りない**: 直進3回で巡航中の右の I 項が +0.30 / +0.18 / +0.15V と正のままだった → FRIC_R 0.41 → 0.53．
- **旋回の摩擦を4つに**: 位置の制御を入れて FRIC_R を上げた後，旋回で回る向きと逆の I 項(左 0.13V，右 0.11V)が出た → 下げた．さらに左回りは合ったが右回りは足りなかった → 回る向きでも分け，2回のログの I 項から補間して決めました．
- **直径**: 1080mm を 300mm/s と 800mm/s で走らせると，どちらも約 2%(21〜22mm)行き過ぎた．速さによらないので換算のずれと判断 → 直径 23.35 → 23.81．トレッドも同じ割合で 64.75 にして，ジャイロとの関係を保ちました．
- **加速の項**: 加速度を 2000/3000/4000mm/s² にしたログで，加速中の I 項が 0.03/0.05/0.09V と**加速度に比例して正** → ACC を 10% 上げて 0.000275．
- **P のゲイン**: ステップで，立ち上がりの間に I 項が 0.19V 溜まり 20% 行き過ぎていた → KP 0.0094 → 0.015．行き過ぎは 12% に減りました．
- **駆動系が変わった**: 右の車軸のねじを締め直したら駆動系が軽くなり，巡航中の I 項が −0.37V に → FRIC_R 0.53 → 0.16．

この時点で，直進 300mm/s で位置のずれ ±0.3mm，向きのずれ 0.4° 以内になりました．

#### (5) 旋回中の機体のモデル(10-08)

車輪のモデルが合ってきた後，探索と最短走行で「スラロームの後に機体がずれる」ことが問題になりました．
車輪とジャイロでは測れないずれなので，壁センサーと補正のログから調べました．

1. **スリップ角を定義した**: 1次遅れ dβ/dt = (K v ω − β)/C(ユーザーの定義)．PC の turn_sim で，SLALOM 試験のログから K，C を合わせられるようにしました．
2. **ずれを測った**: 探索・最短走行 154 回の壁切れ補正と前壁補正を，「小回り1回で出口の向きに a，外へ l ずれる」というモデルで最小二乗に合わせました．小回り1回で前後に 6〜12mm 遅れ，外へ 2〜6mm ずれていました．
3. **スリップだけでは足りないと分かった**: 外へのずれはスリップ(K ≈ 0.015〜0.02)で説明できましたが，そのときの前後の遅れは 3〜4.5mm で，残りの 5〜7mm は説明できませんでした → 「スリップ以外の遅れ」を別の項にしました．
4. **速さによらない1つのモデルにした**: 最初は「選べる速さごとに調整値を持つ」案でしたが，ユーザーの指示で「モデルが正しければ同じモデルで使える」形にしました．500mm/s で外へ 6mm・前後に 10mm を再現するように K = 0.0219 を合わせました．
5. **スリップ以外の遅れの形を直した**: 最初は「横加速度に比例(速さの2乗に比例)」と仮定しました(500mm/s で 5.1mm)．しかし 300〜600mm/s のログでは，必要だった遅れが 8.8/7.7/6.7/6.6mm と**速さによらずほぼ一定**だったので，一定の 7.5mm にしました．

## 4. モデルを合わせる道具

| 道具 | 何を合わせるか | 見方 |
|---|---|---|
| ログの I 項(`i_l`，`i_r`) | FF の各係数 | FF が合っていれば定常の I 項は 0．正なら FF が足りない，負なら多すぎ．巡航中なら FRIC/GAIN，加速中なら ACC |
| 2点の補間 | 旋回の摩擦など | 2つの値で取ったログの I 項を直線で結び，0 になる値を取る |
| 比 | 寸法 | 走った距離の比 → 直径，ジャイロ ÷ 車輪からの角速度 → トレッド |
| `tools/matlab/turn_sim.m` | スリップの K，C | SLALOM 試験のログを重ねて，曲がった後の横のずれ(壁センサー − 車輪とジャイロの軌道)に合わせる(`yc.fit_slip`) |
| 壁切れ補正・前壁補正のログ | 旋回のずれ(前後・外) | 補正の量 = 偏り − ずれ，として多数の回を最小二乗で解く |

調整の手順は `development_log.md` の 6章にあります．

`I 項を目盛りにする` 方法がうまくいくのは，FF を**目標だけから**作っているからです．
FF に実測を混ぜると，I 項が「FF の誤差」だけでなく「FF が実測を追いかけた分」も含み，読み取れなくなります．

## 5. ほかの作り方との比べ(divergence_v3)

ログ機能の元にした divergence_v3(akiaki96．`divergens.md` にコードがある)は，同じ「電圧 FF + PI」でも，モデルの作り方が違います．

| | yuho | divergence_v3 |
|---|---|---|
| モデルの形 | 摩擦 + 速さ + 加速(FF の係数) | 1次遅れ K/(Ts+1) + 不感帯 |
| 決め方 | 定常の電圧と加減速の電圧を測り，I 項で詰める | ステップ応答と PRBS(ランダムな入力)で同定 |
| 速さのゲイン K | 左 1333，右 2000 mm/s/V(計算) | 1519 mm/s/V(PRBS)，1738(ステップ) |
| 時定数 T | 左 0.37 s，右 0.55 s(計算) | 0.445 s |
| PI の決め方 | ログで調整 | IMC(閉ループの時定数 λ を決めて計算) |

別の機体なので値を比べる意味は限られますが，**形と桁はほぼ同じ**です．
yuho の決め方は，FF の係数をそのまま測るので手早く，左右の違いや駆動系の変化に合わせやすい点が利点です．
一方，PI のゲインをモデルから計算していないので，ゲインを変えたときの応答はログを取らないと分かりません．

## 6. 分かっていないこと

| 項目 | 今の状態 |
|---|---|
| 減速中の FF | 減速中は左だけ I 項が負(多すぎ)の傾向がある．加速と減速で ACC を分けるかは未定 |
| 旋回の摩擦の速さによる変化 | 約 100mm/s のログだけ．速さに比例するのか一定なのか未確認 |
| 右回りの摩擦 | いつも左回りの後に回しているので，順番の影響が混ざっている可能性 |
| スリップの K と C | K は 0.01〜0.027 の幅がある(ログの取り方で違う)．C はこの速さでは影響が小さく決められない．横センサーの mm への換算(約 8 AD/mm)も概算 |
| 外への一定のずれ | 速さによらない一定の横のずれ(右 約 4mm，左 約 8mm)がありそう．モデルにはまだ入っていない |
| スリップ以外の遅れ | 7.5mm で一定とした．原因は未確認 |
| 駆動系の変化 | ねじの締め方1つで FRIC が 0.37V 変わった．分解・衝突のたびに合わせ直しが要る |
| 電池の電圧低下 | 走行中に 6.73V まで下がることがある．今の速さでは FF の電圧に余裕があるが，速くするときは確かめる |

次に確かめること: SLALOM_SWEEP(右と左を同じ数ずつ，300〜900mm/s)のログで K，C，一定の横のずれを合わせ直す．
